101 Switching Protocols

The server has accepted the client's request to switch communication protocols.

What is 101 Switching Protocols?

101 Switching Protocols is an informational HTTP response that tells the client the server has agreed to change from one communication protocol to another.

It is most commonly used when upgrading an HTTP connection to WebSocket, but it can also be used for other protocol upgrades.

Browser Example

Browser

GET /chat HTTP/1.1

Upgrade: websocket
Connection: Upgrade

↓

Server

HTTP/1.1 101 Switching Protocols

Upgrade: websocket
Connection: Upgrade

↓

WebSocket Connection Started

HTTP Request

GET /socket HTTP/1.1
Host: example.com
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Version: 13
Sec-WebSocket-Key: xxxxxxxxxxxxxx

Server Response

HTTP/1.1 101 Switching Protocols
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Accept: xxxxxxxxxxxxxx

JavaScript Example

const socket = new WebSocket(
    "wss://example.com/socket"
);

socket.onopen = () => {

    console.log("Connected");

};

The browser automatically performs the HTTP upgrade request. Developers normally do not manually handle the 101 response.

Node.js Server Example

server.on("upgrade",
(request, socket, head) => {

    console.log(
        "Protocol upgraded."
    );

});

cURL Example

curl -i \
-H "Connection: Upgrade" \
-H "Upgrade: websocket" \
https://example.com/socket

Request Flow

Client
   │
   ├── HTTP Request
   │    Upgrade: websocket
   │
Server
   │
   ├── 101 Switching Protocols
   │
Communication
   │
   └── WebSocket Connection

Common Uses

  • Real-time chat applications
  • Live notifications
  • Online multiplayer games
  • Stock market dashboards
  • Live sports score updates
  • IoT device communication

Advantages

  • Real-time two-way communication.
  • Lower latency than repeated HTTP requests.
  • Reduces server and network overhead.
  • Ideal for live applications.

Related Status Codes
