202 Accepted

The request has been accepted for processing, but it has not been completed yet.

What is 202 Accepted?

202 Accepted means the server has received the request and accepted it for processing, but the task has not finished yet.

This status code is commonly used for background jobs, long-running operations, file processing, email sending, report generation and asynchronous APIs.

Browser Example

User uploads a large video

↓

Server

HTTP/1.1 202 Accepted

↓

Video processing started...

↓

User receives notification
when processing finishes.

API Request

POST /api/reports HTTP/1.1
Host: api.example.com
Content-Type: application/json

{
    "report":"sales"
}

Server Response

HTTP/1.1 202 Accepted
Content-Type: application/json

{
    "success": true,
    "message": "Report generation started.",
    "status": "processing"
}

JavaScript (Fetch API)

fetch("/api/reports",{

    method:"POST"

})

.then(response=>{

    console.log(response.status);

});

Node.js (Express)

app.post("/reports",(req,res)=>{

    res.status(202).json({

        message:"Report generation started."

    });

});

PHP Example

http_response_code(202);

echo json_encode([
    "message"=>"Processing started"
]);

cURL Example

curl -X POST https://api.example.com/reports

Best Practices

  • Use 202 only for asynchronous processing.
  • Provide a way to check processing status.
  • Return a Job ID or Tracking ID.
  • Do not use 202 when work is already complete.
  • Return 200 or 201 after the operation finishes.

201 vs 202

Status Meaning
201 Created Resource created immediately.
202 Accepted Request accepted and processing continues.

Related Status Codes

200 OK

Request completed successfully.

201 Created

A new resource was created.
