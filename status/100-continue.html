100 Continue

The server has received the request headers and is ready for the client to continue sending the request body.

What is 100 Continue?

100 Continue is an informational HTTP response. It tells the client that the request headers are valid and the client can continue sending the request body.

It is commonly used when uploading large files so the client doesn't send the entire file unless the server is ready.

Browser Example

Client

POST /upload

Headers Only

↓

Server

HTTP/1.1 100 Continue

↓

Client uploads the file

↓

Server

HTTP/1.1 200 OK

API Example

POST /api/upload HTTP/1.1
Host: api.example.com
Expect: 100-continue
Content-Length: 52428800

Server Response

HTTP/1.1 100 Continue

JavaScript (Fetch API)

fetch("/upload",{
    method:"POST",
    body:file
})
.then(res=>{

    console.log(res.status);

});

Browsers automatically handle 100 Continue. Developers usually don't need to process it manually.

cURL Example

curl -v \
-H "Expect: 100-continue" \
-T large-file.zip \
https://example.com/upload

Request Flow

Client
   │
   ├── Request Headers
   │
Server
   │
   ├── 100 Continue
   │
Client
   │
   ├── Request Body
   │
Server
   │
   └── 200 OK

Real-World Example

  • Uploading a 2 GB video.
  • Sending large backup files.
  • Cloud storage uploads.
  • Large REST API requests.

Why is it Used?

  • Reduces unnecessary data transfer.
  • Improves upload performance.
  • Saves bandwidth.
  • Allows early request validation.
