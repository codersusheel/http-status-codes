429 Too Many Requests

The client has sent too many requests within a given period of time.

What is 429 Too Many Requests?

429 Too Many Requests means the client has exceeded the allowed request limit within a specific time period.

Servers use this status code to prevent abuse, protect APIs, and maintain service availability.

Browser Example

User refreshes a page

100 times in a few seconds

↓

Server Rate Limit

↓

HTTP/1.1 429 Too Many Requests

↓

Please wait before trying again.

API Request

GET /api/weather HTTP/1.1
Host: api.example.com

Server Response

HTTP/1.1 429 Too Many Requests

Retry-After: 60

Content-Type: application/json

{
    "success": false,
    "error": "Rate limit exceeded."
}

JavaScript (Fetch API)

fetch("/api/weather")

.then(response=>{

    if(response.status===429){

        console.log("Too many requests");

    }

});

Node.js (Express)

const rateLimit = require("express-rate-limit");

const limiter = rateLimit({

    windowMs:60*1000,

    max:100

});

app.use(limiter);

PHP Example

http_response_code(429);

header("Retry-After: 60");

echo json_encode([

    "error"=>"Too Many Requests"

]);

cURL Example

curl https://api.example.com/weather

Common Causes

  • API rate limit exceeded.
  • Too many page refreshes.
  • Automated bots.
  • Web scraping.
  • DDoS protection rules.
  • Multiple login attempts.
  • High-frequency polling.

How to Fix

  • Wait before sending another request.
  • Respect the Retry-After header.
  • Reduce request frequency.
  • Implement request caching.
  • Use exponential backoff.
  • Upgrade your API plan if required.
