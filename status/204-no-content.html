204 No Content

What is 204 No Content?

204 No Content means the server successfully processed the request, but there is nothing to return in the response body.

It is commonly used after successful DELETE, PUT, PATCH, or lightweight API requests where no response data is required.

Browser Example

User deletes a file

↓

Server

HTTP/1.1 204 No Content

↓

File deleted successfully

(No response body)

API Request

DELETE /api/users/15 HTTP/1.1
Host: api.example.com
Authorization: Bearer YOUR_TOKEN

Server Response

HTTP/1.1 204 No Content

JavaScript (Fetch API)

fetch("/api/users/15",{

    method:"DELETE"

})

.then(response=>{

    console.log(response.status);

    // 204

});

Node.js (Express)

app.delete("/users/:id",(req,res)=>{

    res.sendStatus(204);

});

PHP Example

http_response_code(204);

// No output
exit;

cURL Example

curl -X DELETE \
https://api.example.com/users/15

Request Flow

Client
   │
   ├── DELETE /users/15
   │
Server
   │
   ├── Deletes Resource
   │
   └── HTTP 204 No Content

Common Uses

  • Delete a record.
  • Update profile information.
  • Save user settings.
  • Logout requests.
  • Mark notifications as read.
  • Remove uploaded files.
  • Successful background operations.

Real-World Examples

Action Status
Delete User 204 No Content
Remove Product 204 No Content
Logout User 204 No Content
Update Settings 204 No Content

Best Practices

  • Use 204 only when no response body is needed.
  • Do not send JSON or HTML with a 204 response.
  • Use 200 if the client expects response data.
  • Use 201 when creating a new resource.
  • Keep DELETE and update endpoints lightweight.

200 vs 204

Status Meaning
200 OK Success with response data.
204 No Content Success without any response body.

Related Status Codes

200 OK

Request completed successfully.

201 Created

New resource created successfully.

202 Accepted

Request accepted for background processing.
